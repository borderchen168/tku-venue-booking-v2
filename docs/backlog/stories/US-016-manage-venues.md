# US-016 承辦人維護場地資料

## User Story(使用者故事)
身為課外組承辦人，我想要新增、編輯與停用可借用場地，以便場地異動（新場地啟用、整修暫停）時，系統的場地清單與申請選項能即時正確。

## 驗收條件（Acceptance Criteria）
### AC1 新增場地
- Given 承辦人已登入
- When 輸入名稱（1～50 字，不可重複）、類別（社團活動場地／擺攤場地）、容納人數（選填，1～99999）、說明（≤ 1000 字）後送出
- Then 建立啟用中的場地，公開場地清單（US-001）立即顯示

### AC2 編輯場地
- Given 場地「覺軒花園教室」存在
- When 承辦人修改容納人數與說明
- Then 更新成功，既有申請不受影響

### AC3 停用場地
- Given 場地有未來的佔用中申請
- When 承辦人停用該場地
- Then 系統先列出受影響的未來申請並要求確認；停用後公開清單不顯示、不能再申請（US-004 AC14），既有申請不自動取消（承辦人可用 US-012 處理）

### AC4 名稱重複或欄位不合法被拒絕
- Given 已有場地「驚聲廣場」
- When 新增同名場地，或欄位超出長度與範圍
- Then 系統拒絕並逐欄顯示錯誤

### AC5 不可刪除場地
- Given 場地曾有申請紀錄
- When 承辦人嘗試刪除
- Then 系統不提供刪除，只能停用（保留借用紀錄的完整性）

### AC6 學生不能維護場地
- Given 使用者角色為學生或未登入
- When 存取場地管理頁或端點
- Then 分別回應 403（記錄權限拒絕日誌）或導向登入頁

### AC7 CSRF 防護
- Given 承辦人送出的請求缺少 CSRF Token
- When 新增、編輯或停用場地
- Then 系統回應 403，資料不變

## 商業規則與限制
- 管理要點第二點：可借用場地為社團活動場地與海報街；各樓館教室不納入。

## 假設
- 初始 8 個場地由 migration 匯入（見 US-001），本 Story 提供後續維護介面。

## 相依項目

## 資安考量
- 權限：僅 `staff`。
- 輸入驗證：Pydantic 白名單；說明欄位輸出時 autoescape。
- CSRF Token 必驗。
