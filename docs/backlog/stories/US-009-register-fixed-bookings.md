# US-009 承辦人登錄學期固定借用（固定保留時段）

## User Story(使用者故事)
身為課外組承辦人，我想要把學期初協調會排定的固定借用（例如每週二 18:00–21:00）登錄為該社團的「固定保留時段」，以便其他社團無法申請這些時段，而該社團每次使用前仍依規定送出申請並經我審核（R-11、R-12）。

## 驗收條件（Acceptance Criteria）
### AC1 批次登錄每週固定保留時段
- Given 承辦人已登入，協調會決議「熱舞社」本學期每週二 18:00–21:00 使用「五虎崗舞蹈教室」，期間 2027-03-02～2027-06-29
- When 承辦人選擇社團、場地、星期、時段、起訖日期，填寫用途說明（例如「熱舞社例行社課」）並送出
- Then 系統預覽將保留的日期清單；承辦人確認後，為每個日期建立一筆「固定保留」紀錄（**不是**申請，也不是已核准借用），記錄登錄人；寫入安全日誌

### AC2 自動略過不開放日期（R-03～R-05）
- Given 期間內某些週二落在國定假日或考試週等不開放期間（US-017）
- When 系統產生預覽
- Then 這些日期被略過，並在預覽中列出「略過日期與原因」

### AC3 與既有佔用衝突時整批不建立
- Given 期間內某個週二 19:00–20:00，該場地已有其他社團審核中或已核准的申請，或已有其他固定保留時段
- When 承辦人確認登錄
- Then 系統不建立任何一筆，列出所有衝突日期與對方資訊，請承辦人處理（取消衝突借用或調整條件）後再登錄；檢查與寫入在同一個 `BEGIN IMMEDIATE` transaction

### AC4 時段與期間規則（R-01、學期區間）
- Given 承辦人輸入 21:00–22:30、非 30 分鐘倍數的時間，或起訖日期不在同一個學期區間內（上學期 9/1～12/31、下學期 3/1～6/30）
- When 送出
- Then 系統拒絕並提示正確範圍（08:00–22:00、30 分鐘為單位、期間須在同一學期內）

### AC5 借用狀況顯示固定保留（US-002）
- Given 熱舞社在 2027-03-09（二）18:00–21:00 有固定保留時段，尚未送出該場次的申請
- When 訪客查看五虎崗舞蹈教室該週的借用狀況
- Then 該時段標示「固定保留（熱舞社）」，不顯示為可申請；若熱舞社已對該場次送出申請，則改顯示該申請的狀態（審核中／已核准）

### AC6 社團對自己的保留時段送出申請（US-004 流程）
- Given 熱舞社在 2027-03-09 18:00–21:00 有固定保留時段；熱舞社負責人於期限內（R-13）登入
- When 他依 US-004 以熱舞社名義申請五虎崗舞蹈教室 2027-03-09 18:00–21:00（或保留時段內的一部分，例如 18:00–20:00）
- Then 申請成功建立為「審核中」，保留時段不視為重疊；其餘規則（R-01、R-03～R-05、R-13、與其他申請不重疊）照常檢查；須經承辦人審核（US-006）核准後才算借用成立

### AC7 其他社團申請保留時段被拒絕
- Given 熱舞社在 2027-03-09 18:00–21:00 有固定保留時段
- When 吉他社負責人申請五虎崗舞蹈教室 2027-03-09 19:00–20:00
- Then 系統拒絕，顯示「該時段已被借用」（或「該時段為固定保留時段」），不建立申請；併發情境下同樣不得建立重疊

### AC8 登錄保留不受 5 個工作天限制
- Given 固定保留時段由承辦人登錄
- When 期間起日距今不足 5 個工作天
- Then 系統仍允許登錄（R-13 只適用社團送出的申請，含 AC6 的每次申請）

### AC9 學生不能登錄固定保留
- Given 使用者角色為學生
- When 開啟固定保留登錄頁或送出登錄請求
- Then 系統回應 403，記錄權限拒絕的安全日誌

### AC10 欄位與期間驗證
- Given 承辦人輸入起日晚於迄日、用途說明為空或超過 100 字、或社團／場地不存在或已停用
- When 送出
- Then 系統拒絕並逐欄顯示錯誤

### AC11 承辦人可個別釋出保留日期
- Given 熱舞社某學期的固定保留時段
- When 承辦人釋出其中某一天（須填原因 1～500 字）
- Then 只釋出該日，其餘日期不受影響；若該日已有熱舞社的審核中或已核准申請，系統提示需先以 US-012 取消該申請

### AC12 CSRF 防護
- Given 請求缺少或帶錯誤的 CSRF Token
- When 送出登錄或釋出請求
- Then 系統回應 403，資料不變

## 商業規則與限制
- R-11：學期初協調會排定固定借用；空餘時段開放社團臨時借用（US-004）。
- R-12：固定與臨時借用都須經承辦人審核。本系統中「固定保留」只代表時段保留給該社團；**社團每次使用前仍須對該場次送出申請（US-004），經承辦人審核（US-006）核准才算借用成立**（使用者決定，2026-11-06）。
- 固定保留時段對其他社團視為佔用；對被保留的社團不視為重疊。
- 學期區間：上學期 9/1～12/31、下學期 3/1～6/30（使用者決定，暫定）。

## 假設
- 第一版只支援「每週重複」一種規則。
- 社團的申請被駁回或取消後，固定保留時段**仍保留**給該社團（可重新申請），只有承辦人能釋出保留（AC11）。
- 社團對保留時段的每次申請仍受 R-13（5 個工作天）限制，與一般申請相同。
- 固定保留期間以單一學期為單位；跨學期需分別登錄。

## 資安考量
- 權限：登錄與釋出僅 `staff`，service 層檢查；AC6 的「自己的保留時段」判斷依申請的 `club_id` 與保留時段的社團比對，且申請人須為該社團負責人（防止竄改 `club_id` 取得他社保留時段，CWE-639）。
- 輸入驗證：星期為 0～6 列舉、時間與日期格式、期間限單一學期（防止一次產生過多資料）。
- 交易：整批建立具原子性，禁止部分寫入；保留與申請的重疊檢查共用 `BEGIN IMMEDIATE` transaction。
- CSRF Token 必驗。
