# US-004 學生線上申請臨時借用活動場地

## User Story(使用者故事)
身為社團負責人（學生），我想要上網以社團名義申請借用活動場地的某個時段，以便不必跑紙本流程，並立即知道該申請是否符合開放時間與申請期限。

## 驗收條件（Acceptance Criteria）
### AC1 成功送出申請
- Given 學生「王小明」已登入，且是「吉他社」的負責人；今天是 2026-11-09（一）
- When 他選擇社團「吉他社」、場地「驚聲廣場」、日期 2026-11-16（一）、時段 18:00–20:00，填寫活動名稱、活動說明、預估人數後送出
- Then 系統建立一筆狀態為「審核中」的申請，記錄申請人與社團，畫面顯示申請編號與「已送出，待課外組承辦人審核（R-12）」；該時段在借用狀況頁（US-002）顯示為審核中；並寫入安全日誌（預約異動事件）

### AC2 未登入不能申請
- Given 訪客未登入
- When 開啟申請頁或直接對申請端點送出 POST
- Then 開啟頁面時導向登入頁；POST 請求被拒絕（401 或導向登入），不建立任何申請

### AC3 非社團負責人或竄改社團不能申請
- Given 學生「王小明」只是「吉他社」的負責人
- When 他竄改表單，以「熱舞社」的 `club_id` 送出申請
- Then 系統回應 403，不建立申請，並記錄權限拒絕的安全日誌

### AC4 承辦人帳號不使用本流程
- Given 使用者角色為承辦人（staff）
- When 對學生申請端點送出申請
- Then 系統回應 403（承辦人登錄固定保留時段請用 US-009）

### AC5 時段重疊被拒絕
- Given 驚聲廣場 2026-11-16 已有一筆「審核中」或「已核准」的申請 18:00–20:00
- When 另一社團申請同場地同日 19:00–21:00（或 17:00–18:30、或 18:00–20:00）
- Then 系統拒絕申請，顯示「該時段已被借用」，不建立申請

### AC6 相鄰時段可申請
- Given 驚聲廣場 2026-11-16 已有 18:00–20:00 的佔用申請
- When 另一社團申請同場地同日 20:00–22:00
- Then 申請成功（時段以 [開始, 結束) 半開區間判斷，相鄰不算重疊）

### AC7 併發申請只有一筆成功
- Given 兩位不同社團的負責人同時對驚聲廣場 2026-11-16 18:00–20:00 送出申請
- When 兩個請求併發處理
- Then 只有一筆申請成功，另一筆收到「該時段已被借用」；資料庫中不存在重疊的佔用申請（AGENTS.md 1.3：同一 transaction 以 `BEGIN IMMEDIATE` 檢查後寫入，需有併發測試）

### AC8 超出開放時間被拒絕（R-01）
- Given 學期間開放時段為 08:00–22:00
- When 學生申請 07:30–09:00，或 21:00–22:30，或跨日時段
- Then 系統拒絕，顯示「可借用時段為 08:00–22:00，且須於 22:00 前撤場」

### AC9 時段格式不合法被拒絕
- Given 學生填寫申請
- When 開始時間不早於結束時間、或時間不是 30 分鐘的整數倍（例如 18:15）
- Then 系統拒絕並提示正確格式

### AC10 不開放日期被拒絕（R-03、R-04、R-05）
- Given 承辦人已設定 2026-12-25 為國定假日、2026-12-14～2026-12-27 為「期末考週及前一週」、某日為「大型考試」不開放
- When 學生申請上述任一日期的任何時段
- Then 系統拒絕，顯示「該日期不開放借用」與原因類型

### AC11 未達 5 個工作天被拒絕（R-13）
- Given 今天是 2026-11-10（二），活動日期為 2026-11-16（一）；由活動日往前推 5 個工作天為 2026-11-09（一）
- When 學生送出申請
- Then 系統拒絕，顯示「一般校內活動須於活動前 5 天（不含假日）提出申請，本活動最晚申請日為 2026-11-09」

### AC12 剛好第 5 個工作天可申請（R-13 邊界）
- Given 今天是 2026-11-16（一），活動日期為 2026-11-21（六）；由活動日往前推 5 個工作天為 2026-11-16（一）
- When 學生送出申請
- Then 申請成功

### AC13 工作天只看週一～週五，不受不開放日期影響（R-13）
- Given 承辦人已將 2026-11-18（三）設為「國定假日」類型的不開放日期；今天是 2026-11-16（一），活動日期為 2026-11-23（一）
- When 學生送出申請
- Then 最晚申請日為 2026-11-16（往前依序 11/20、11/19、11/18、11/17、11/16，國定假日的 11/18 仍計入工作天），申請成功；週六、週日一律不計入，也不考慮補班日

### AC14 場地停用或不存在被拒絕
- Given 場地已停用或 id 不存在
- When 學生申請該場地
- Then 系統拒絕（404 或 422），不建立申請

### AC15 欄位驗證
- Given 學生填寫申請表
- When 活動名稱為空或超過 100 字、活動說明為空或超過 1000 字、預估人數不是 1～9999 的整數、或超過場地容納人數（有設定時）
- Then 系統拒絕並逐欄顯示錯誤，已填資料保留（密碼類以外）

### AC16 CSRF 防護
- Given 學生已登入
- When 送出的申請請求缺少或帶有錯誤的 CSRF Token
- Then 系統回應 403，不建立申請

## 商業規則與限制
- R-01：08:00–22:00，22:00 前須撤場。
- R-02：學期區間為每年 9/1～12/31、3/1～6/30，其餘日期為寒暑假，開放時段以 US-018 的設定為準，未設定即不開放（US-018 完成後生效，見待釐清）。
- R-03～R-05：不開放日期／期間由 US-017 維護，只決定「該日能否借用」。
- R-10、R-15：附件（企畫書、場地配置文件）上傳見 US-007。
- R-11、R-12：本流程同時用於臨時借用與固定保留時段的每次使用；送出後都需承辦人審核（US-006）。
- R-13：申請日（Asia/Taipei 日期）須早於或等於「活動日往前推算第 5 個工作天」（活動日本身不計）；**工作天＝週一～週五**，不扣除國定假日或其他不開放日期，也不考慮補班。
- R-16：未核准前不得使用，畫面需明示。
- R-20：送出後不可修改場地、日期、時段或轉給其他社團；需改期請取消（US-011）後重新申請。
- 申請狀態只有：審核中、已核准、已駁回、已取消；佔用時段的狀態：審核中、已核准。駁回後不提供補件，由社團重新申請（重新申請仍受 R-13 限制）。
- 時間以 UTC 儲存，顯示與規則判斷（日期、工作天）以 Asia/Taipei 進行。

### 固定保留時段（US-009 完成後生效，不屬於本 Story 的 Sprint 1 驗收）
- 社團對**自己的**固定保留時段送出申請時，該保留時段不視為重疊，其餘規則（R-01、R-03～R-05、R-13、與其他申請不重疊）照常檢查。
- 其他社團申請與固定保留時段重疊的時段時，系統拒絕。
- 對應的驗收條件定義於 US-009 AC6、AC7；重疊檢查的擴充點見 T-018。

## 假設
- 採 README 第 4 節建議：以**社團**為申請單位，申請人須為該社團負責人。
- 「審核中」申請即佔用時段（先申請先佔）。
- 時段以 30 分鐘為單位，單筆申請限同一天、單一場地、單一時段；需多時段請分次申請。
- 不檢查 R-14（校外活動 10 天）與 R-18（海報街攤商比例），不在第一版範圍。
- 停權社團不能申請的規則於 US-019 加入。
- 本階段工作天＝週一～週五，不考慮國定假日與補班（使用者決定，2026-11-06）。

## 資安考量
- 權限：僅 `student` 角色且為所選社團的負責人可申請；service 層檢查，預設拒絕（A01、CWE-862/863/639）。
- 輸入驗證：全部欄位以 Pydantic schema 白名單驗證（型別、長度、範圍、日期時間格式）。
- 資料一致性：重疊檢查與寫入在同一個 `BEGIN IMMEDIATE` transaction，禁止字串拼接 SQL。
- CSRF Token 必驗；日誌記錄申請建立事件（申請 id、使用者 id、社團 id），不記錄完整個資。
