# US-013 使用者登入與登出

## User Story(使用者故事)
身為學生或課外組承辦人，我想要以本機帳號安全地登入與登出系統，以便使用申請、審核、取消等需要身分的功能，且我的帳號不會被他人冒用。

## 驗收條件（Acceptance Criteria）
### AC1 成功登入
- Given 帳號 `412345678`（學生）已啟用，密碼正確
- When 使用者在登入頁輸入帳號密碼送出
- Then 登入成功，**建立全新的 Session（新 Session ID 與新 CSRF Token）**；若請求帶有舊的 Session Cookie，舊 Session 一併作廢（防 Session Fixation）；以 303 導向首頁（或 `next` 參數指定的站內相對路徑，不合法時改導向首頁），並顯示使用者顯示名稱（`display_name`）與角色對應的選單（學生：申請場地；承辦人：不開放期間管理）；記錄登入成功的安全日誌
- 且 Sprint 1 尚未完成的功能項目（學生「我的申請」〔US-005〕、承辦人「待審核」〔US-006〕）依 routes.md §2.1 設計**不顯示於選單**（主對話定案，2026-11-06），不得出現可點擊後得到 404 或錯誤頁的連結；Sprint 1 承辦人的「管理功能」至少包含「不開放期間管理」（US-017）

### AC2 登入失敗不透露帳號是否存在
- Given 帳號不存在，或帳號存在但密碼錯誤
- When 使用者送出登入
- Then 兩種情況都回應 **HTTP 400** 並重新顯示登入頁，訊息相同「帳號或密碼錯誤」；回應內容除 CSRF Token 值外逐字相同；帳號欄位回填原始輸入（**截斷至前 50 字**，經 autoescape 輸出），密碼欄位不回填；回應時間不應有明顯差異；記錄登入失敗的安全日誌（不記錄輸入的密碼）
- 註：系統忙碌（密碼雜湊名額已滿）時的 HTTP 503 回應不屬於登入失敗，見 AC13

### AC3 連續失敗鎖定（Rate Limit）
- Given 同一帳號在 15 分鐘內連續登入失敗 5 次
- When 第 6 次嘗試登入（即使密碼正確）
- Then 系統拒絕登入 15 分鐘，回應與 AC2 相同（HTTP 400、「帳號或密碼錯誤」），不顯示「帳號已鎖定」或剩餘次數，也不透露帳號是否存在；記錄鎖定事件
- 且 同時大量送出的錯誤密碼請求，實際進行的密碼驗證次數不超過 5 次（併發情境需有測試）
- 且 不存在的帳號同樣在 5 次失敗後被「鎖定」（行為與存在的帳號一致）

### AC4 停用帳號不能登入
- Given 帳號已被承辦人停用（US-014）
- When 使用者以正確密碼登入
- Then 回應與 AC2 相同（HTTP 400、「帳號或密碼錯誤」），不建立 Session

### AC5 登出銷毀 Session
- Given 使用者已登入
- When 按下「登出」（POST 並帶 CSRF Token）
- Then 伺服器端 Session 被銷毀、Cookie 清除，使用舊 Session Cookie 再存取需登入的頁面時導向登入頁

### AC6 閒置逾時
- Given 使用者登入後閒置超過 30 分鐘（逾時值可由 `.env` 設定）
- When 再次存取需登入的頁面
- Then 導向登入頁並提示「登入已逾時，請重新登入」

### AC7 Cookie 安全屬性
- Given 使用者登入成功
- When 檢查回應的 Session Cookie
- Then 具備 `HttpOnly`、`SameSite=Lax`、`Path=/`，不設定 `Domain`，也不設定 `Max-Age`／`Expires`（逾時由伺服器判斷）；正式環境（`.env` 環境別為 production）另具備 `Secure`，且 Cookie 名稱必須以 `__Host-` 開頭
- 且 正式環境設定的 Cookie 名稱不以 `__Host-` 開頭，或未啟用 `Secure` 時，系統拒絕啟動

### AC8 登入／登出 CSRF 防護
- Given 登入或登出請求缺少或帶錯誤的 CSRF Token，或未先開啟登入頁（沒有登入前 Token 對應的 Cookie）就直接送出登入，或登入前 Token 已逾期
- When 送出
- Then 系統回應 403，不登入也不登出
- 且 登出請求必須帶有效的已登入 Session 與其 CSRF Token；沒有有效 Session 時（例如以登入前 Token 送出登出）回應 403

### AC9 建立第一個承辦人帳號
- Given 系統剛部署，尚無任何帳號
- When 管理者執行管理指令（例如 `python -m app.cli create-staff`），依提示輸入帳號、姓名與密碼
- Then 建立一個承辦人帳號，密碼以 argon2 雜湊儲存；密碼少於 8 字元或屬常見密碼時拒絕建立

### AC10 輸入驗證
- Given 帳號為空、超過 50 字、或含白名單以外字元（僅允許英數字與 `._-`）
- When 送出登入
- Then 回應與 AC2 相同（HTTP 400、「帳號或密碼錯誤」，帳號回填截斷至前 50 字），不建立 Session，也不回應任何可推測帳號是否存在的資訊
- 且 密碼為空或超過 128 字元時同樣回應與 AC2 相同的結果（密碼長度上限防止雜湊 DoS）

### AC11 登入前不建立伺服器端 Session
- Given 訪客未登入
- When 瀏覽公開頁面、開啟登入頁（`GET /login`），或登入失敗
- Then 系統不建立任何伺服器端 Session 資料（登入頁的 CSRF 防護改以不寫入資料庫的登入前 Token 達成）；只有登入成功才建立 Session

### AC12 絕對逾時
- Given 使用者登入後持續操作（未閒置），但距離登入已超過 8 小時（可由 `.env` 設定，且不得小於閒置逾時）
- When 再次存取需登入的頁面
- Then 導向登入頁並提示「登入已逾時，請重新登入」

### AC13 系統忙碌時回應 503
- Given 同時進行的密碼雜湊運算已達上限（名額已滿）
- When 使用者送出登入
- Then 系統不排隊等待，立即回應 **HTTP 503** 並顯示「系統忙碌，請稍後再試」，附 `Retry-After` 標頭；不建立 Session
- 且 此判斷發生在讀取任何帳號資料之前，帳號存在與否、密碼正確與否、是否鎖定都得到相同的 503 回應，不洩漏帳號狀態
- 且 此回應**不計入**該帳號的登入失敗次數（不影響 AC3 鎖定計數）

## 商業規則與限制
- 角色：`student`（學生／社團負責人）、`staff`（課外組承辦人）。
- AGENTS.md 2.3 認證與 Session 規範（ASVS Level 2）。

## 假設
- 本機帳號，帳號格式為學號或職員編號；學生不能自行註冊。
- 鎖定門檻（15 分鐘內 5 次、鎖 15 分鐘）、閒置逾時（30 分鐘）與絕對逾時（8 小時）為第一版預設值，可由 `.env` 調整。
- Sprint 1 的學生帳號與社團資料可先以管理指令建立，維護介面於 US-014 提供。
- Sprint 1 解除鎖定以管理指令 `unlock-user` 處理；承辦人 Web 解鎖介面見 US-022，應用程式層 IP 頻率限制見 US-021。
- 已知並接受的風險：知道學號的人可故意輸錯密碼鎖住他人帳號（帳號鎖定型 DoS）；Sprint 1 以反向代理 IP 頻率限制、CLI 解鎖與告警規則緩解（ADR-005）。
- 以下 AC 文字依 T-001 架構設計修正（2026-11-06）：登入失敗一律 HTTP 400 且內容相同、帳號回填截斷 50 字、登入前不建立 Session、production Cookie 名稱 `__Host-` 前綴、絕對逾時、系統忙碌回 503（AC13）（見 ADR-001、ADR-002、ADR-005 §6）。

## 資安考量
- 權限：登入前只能存取公開頁面；需登入的 route 預設拒絕。
- 密碼：argon2 雜湊（`argon2-cffi`），禁止明碼或可逆加密；日誌不得記錄密碼、Session ID、CSRF Token。
- Session：登入後重新產生 Session ID（防 Session Fixation(會話固定)，CWE-384）；登出銷毀；閒置逾時。
- 輸入驗證：帳號長度與字元白名單；密碼長度上限 128 防止雜湊 DoS；同時進行的密碼雜湊運算數量設上限（CWE-400）。
- `next` 參數只接受站內相對路徑，防 Open Redirect(開放式重新導向)（CWE-601）。
- 管理指令需輸入密碼者（例如 `create-staff`）只能在互動式終端機執行，避免密碼寫在腳本或管線中。
