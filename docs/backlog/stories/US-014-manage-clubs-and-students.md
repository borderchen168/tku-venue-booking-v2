# US-014 承辦人維護社團與學生帳號

## User Story(使用者故事)
身為課外組承辦人，我想要建立社團、建立學生帳號並指定為社團負責人，以便只有社團負責人能以社團名義申請場地，且負責人交接時能即時調整。

## 驗收條件（Acceptance Criteria）
### AC1 建立社團
- Given 承辦人已登入
- When 輸入社團名稱（1～50 字，不可重複）與社團代碼後送出
- Then 建立一個啟用中的社團

### AC2 社團名稱重複被拒絕
- Given 已有社團「吉他社」
- When 承辦人再建立「吉他社」
- Then 系統拒絕並提示「社團名稱已存在」

### AC3 建立學生帳號並設定初始密碼
- Given 承辦人已登入
- When 輸入學號（帳號）、姓名、Email（校內信箱格式）與初始密碼後送出
- Then 建立 `student` 角色帳號，密碼以 argon2 雜湊，帳號標記為「首次登入須變更密碼」（US-015）；初始密碼少於 8 字元或屬常見密碼時拒絕

### AC4 指定與移除社團負責人
- Given 社團「吉他社」與學生帳號 `412345678` 都存在
- When 承辦人將該學生加入吉他社負責人（一個社團可有多位負責人，一位學生可負責多個社團），或移除
- Then 該學生申請時（US-004）的社團選單隨之增減；移除後不能再以該社團申請新的借用，但既有申請不受影響

### AC5 停用學生帳號
- Given 學生帳號啟用中
- When 承辦人停用該帳號
- Then 該學生無法登入（US-013 AC4），其既有 Session 立即失效；既有申請保留

### AC6 重設學生密碼
- Given 學生忘記密碼
- When 承辦人為其設定新的臨時密碼
- Then 密碼更新並標記「首次登入須變更密碼」，該學生既有 Session 失效

### AC7 學生不能使用管理功能
- Given 使用者角色為學生
- When 存取社團或帳號管理頁面或端點
- Then 系統回應 403，並記錄權限拒絕的安全日誌

### AC8 輸入驗證與 CSRF
- Given 學號不符格式（英數字 1～50 字）、Email 格式錯誤、姓名超過 50 字，或請求缺少 CSRF Token
- When 送出
- Then 分別回應欄位錯誤（422）或 403，不寫入資料

## 商業規則與限制
- 申請單位為社團，申請人須為社團負責人（README 第 4 節）。

## 假設
- 採 README 第 4 節建議：系統建立「社團」，學生以社團負責人身分申請。
- 學生不能自行註冊；帳號由承辦人建立（第一版不做批次匯入）。
- 不建立承辦人帳號的管理介面；承辦人帳號以管理指令建立（US-013 AC9）。
- 社團停權狀態見 US-019。

## 資安考量
- 權限：僅 `staff`，service 層檢查。
- 個資：姓名、學號、Email 僅承辦人與本人可見，日誌不記錄完整個資。
- 輸入驗證：所有欄位以 Pydantic 白名單驗證；密碼規則同 AGENTS.md 2.3。
- 停用與重設密碼時使該使用者所有 Session 失效。
