# US-011 學生取消自己的借用申請

## User Story(使用者故事)
身為社團負責人（學生），我想要取消我自己送出的場地申請，以便活動取消或改期時及時釋出場地給其他社團，並履行通知課外組的義務（R-21）。

## 驗收條件（Acceptance Criteria）
### AC1 取消審核中的申請
- Given 學生「王小明」已登入，他的申請 50 狀態為「審核中」，活動日期為 2026-11-30
- When 他在申請明細按「取消申請」並確認
- Then 狀態變為「已取消」，記錄取消人與時間，該時段立即釋放（借用狀況頁顯示可申請）；寫入安全日誌

### AC2 取消已核准的申請須填理由（R-21）
- Given 王小明的申請 51 狀態為「已核准」，活動日期為 2026-11-30，今天是 2026-11-20
- When 他按「取消申請」並填寫取消理由（1～500 字）
- Then 狀態變為「已取消」，時段釋放，承辦人可在申請明細與取消清單看到理由

### AC3 已核准申請未填理由被拒絕
- Given 申請 51 狀態為「已核准」
- When 王小明取消但理由為空白
- Then 系統拒絕並提示「請填寫取消理由」，狀態不變

### AC4 活動前 3 天內取消標記為逾期取消（R-21）
- Given 王小明的申請 52 狀態為「已核准」，活動日期為 2026-11-20
- When 他在 2026-11-18（含）之後、活動開始前取消（最遲通知日為 2026-11-17）
- Then 系統先提示「已超過活動前 3 天的通知期限，將記錄為逾期取消」，確認後狀態變為「已取消」並標記「逾期取消」，承辦人可篩選查看

### AC5 期限內取消不標記逾期
- Given 申請活動日期為 2026-11-20
- When 學生在 2026-11-17（含）之前取消
- Then 狀態變為「已取消」，不標記逾期取消

### AC6 非本人不能取消（IDOR）
- Given 申請 50 屬於王小明
- When 學生「李小華」（即使與王小明同社團）以網址或竄改請求取消申請 50
- Then 系統回應 404，狀態不變，並記錄權限拒絕的安全日誌

### AC7 未登入不能取消
- Given 訪客未登入
- When 對取消端點送出 POST
- Then 導向登入頁或回應 401，狀態不變

### AC8 已開始、已結束或終結狀態不能取消
- Given 申請已駁回、已取消，或活動開始時間已過
- When 申請人送出取消
- Then 系統回應 409，提示「此申請目前無法取消」，狀態不變

### AC9 CSRF 防護
- Given 學生已登入
- When 取消請求缺少或帶錯誤的 CSRF Token
- Then 系統回應 403，狀態不變

## 商業規則與限制
- R-20：不提供改期、換場地、轉借；需變更請取消後重新申請（重新申請仍受 R-13 限制）。
- R-21：因正當理由取消，最遲於活動前 3 天通知課外組。
- 可取消狀態：審核中、已核准。

## 假設
- 採 README 第 4 節建議：活動前 3 天內**仍允許取消，但標記為逾期取消**。
- 「活動前 3 天」以日曆天計算（規定未註明不含假日）：最遲通知日 = 活動日 − 3 天（Asia/Taipei 日期），晚於該日取消即為逾期。
- 「自己的申請」= 本人送出的申請；同社團其他負責人不能取消（依使用案例 3A 字面解讀）。
- 系統內取消紀錄即視為「通知課外組」，不另寄 Email。
- 逾期取消**不**自動計入 R-22 的「未告知放棄」次數（R-22 由承辦人登記，見 US-020）。

## 資安考量
- 權限：service 層以 `applicant_id = 目前使用者` 驗證擁有者，預設拒絕（A01、CWE-639）。
- 輸入驗證：理由 1～500 字；申請 id 為正整數。
- 交易：狀態轉換以目前狀態為條件更新，避免與承辦人審核併發衝突。
- CSRF Token 必驗。
