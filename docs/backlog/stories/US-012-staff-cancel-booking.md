# US-012 承辦人取消已申請或已核准的借用

## User Story(使用者故事)
身為課外組承辦人，我想要取消已被申請或已核准的場地借用並說明原因，以便在臨時不開放（例如大型考試、場地維修）或社團被停權時收回場地，並讓申請人知道原因。

## 驗收條件（Acceptance Criteria）
### AC1 取消已核准的借用須填原因
- Given 承辦人已登入，申請 60 狀態為「已核准」，活動尚未開始
- When 承辦人按「取消借用」，選擇原因類別（不開放日期／場地因素／停權／其他）並填寫說明（1～500 字）後確認
- Then 狀態變為「已取消」，記錄取消人為承辦人、原因與時間，時段立即釋放；寫入安全日誌

### AC2 申請人在系統內收到通知
- Given 申請 60 已被承辦人取消
- When 申請人登入並查看「我的申請」（US-005）
- Then 該申請顯示「已由課外組取消」與原因；清單上有醒目標示（例如「有新的狀態異動」）直到申請人開啟明細

### AC3 取消審核中的申請
- Given 申請狀態為「審核中」
- When 承辦人取消並填寫原因
- Then 狀態變為「已取消」，時段釋放

### AC4 未填原因被拒絕
- Given 承辦人取消任一申請
- When 原因說明為空白或未選類別
- Then 系統拒絕並提示「請填寫取消原因」，狀態不變

### AC5 學生不能使用承辦人取消功能
- Given 使用者角色為學生
- When 對承辦人取消端點送出請求（即使是自己的申請）
- Then 系統回應 403，狀態不變，並記錄權限拒絕的安全日誌

### AC6 終結狀態或已開始不能取消
- Given 申請已駁回、已取消，或活動開始時間已過
- When 承辦人取消
- Then 系統回應 409，狀態不變

### AC7 CSRF 與登入
- Given 請求缺少 CSRF Token，或使用者未登入
- When 送出取消請求
- Then 分別回應 403／導向登入頁，狀態不變

### AC8 承辦人取消不標記逾期
- Given 承辦人在活動前 3 天內取消
- When 取消完成
- Then 不標記「逾期取消」（逾期取消只用於社團自行取消，US-011）

## 商業規則與限制
- R-04、R-05：臨時不開放時，承辦人可取消已核准借用。
- R-31：課外組可取消社團的場地借用權利（停權本身見 US-019）。

## 假設
- 採 README 第 4 節建議：取消時**必須填寫原因並通知申請人**；第一版以系統內通知呈現，不寄 Email。
- 新增不開放期間時，第一版**不自動**取消期間內既有借用；系統在 US-017 列出受影響借用，由承辦人以本 Story 逐筆取消。

## 資安考量
- 權限：僅 `staff`，service 層檢查。
- 輸入驗證：原因類別為列舉白名單；說明 1～500 字。
- 日誌：記錄取消事件（申請 id、承辦人 id、原因類別）。
- CSRF Token 必驗。
