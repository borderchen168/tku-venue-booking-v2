# US-005 學生查看自己的申請與審核狀態

## User Story(使用者故事)
身為社團負責人（學生），我想要查看我送出的所有申請及其審核狀態與原因，以便知道活動是否可以舉辦、是否需要修正後重新申請或改期。

## 驗收條件（Acceptance Criteria）
### AC1 查看我的申請清單
- Given 學生「王小明」已登入，且曾送出 3 筆申請（審核中、已核准、已駁回各 1 筆）
- When 他開啟「我的申請」頁
- Then 列出這 3 筆申請：申請編號、社團、場地、日期、時段、活動名稱、狀態、送出時間，依活動日期由近到遠排序

### AC2 查看申請明細與原因
- Given 某筆申請被駁回（或被承辦人取消），承辦人填有原因
- When 學生開啟該申請明細
- Then 顯示完整申請內容、狀態異動歷程（時間、狀態、原因），作為系統內通知

### AC3 只能看到自己的申請（IDOR）
- Given 學生「李小華」的申請編號為 42
- When 學生「王小明」以網址直接存取申請 42 的明細
- Then 系統回應 404（不透露該申請是否存在），並記錄權限拒絕的安全日誌

### AC4 未登入不能查看
- Given 訪客未登入
- When 開啟「我的申請」頁或任何申請明細
- Then 導向登入頁

### AC5 依狀態篩選
- Given 學生有多種狀態的申請
- When 選擇只看「審核中」
- Then 只列出審核中的申請；狀態參數不在白名單內時回應 422

## 商業規則與限制
- R-16：未核准的申請，畫面明示「未經核准不得使用場地」。
- 申請狀態只有：審核中、已核准、已駁回、已取消（篩選白名單即此四種）。不提供退回補件；被駁回的申請於明細提示「請修正後重新申請」並連結至申請頁（US-004）。

## 假設
- 「自己的申請」定義為**本人送出**的申請；同社團其他負責人的申請不在清單中（與 US-011 取消權限一致）。
- 系統內通知以「狀態異動歷程」呈現，第一版不寄送 Email。

## 相依項目

## 資安考量
- 權限：查詢一律以 `applicant_id = 目前使用者` 為條件，於 service 層檢查擁有者（A01、CWE-639）。
- 輸入驗證：申請 id 為正整數，狀態篩選為列舉白名單。
- 輸出：承辦人填寫的原因經 autoescape 輸出。
