# US-015 使用者變更密碼（含首次登入強制變更）

## User Story(使用者故事)
身為學生或承辦人，我想要變更自己的密碼，並在首次登入時被要求更換承辦人給的初始密碼，以便只有我自己知道密碼，降低帳號被冒用的風險。

## 驗收條件（Acceptance Criteria）
### AC1 變更密碼成功
- Given 使用者已登入
- When 輸入正確的目前密碼與符合規則的新密碼（兩次輸入一致）後送出
- Then 密碼更新（argon2 雜湊），重新產生 Session ID，該使用者其他 Session 失效；記錄安全日誌

### AC2 目前密碼錯誤被拒絕
- Given 使用者已登入
- When 輸入錯誤的目前密碼
- Then 系統拒絕，密碼不變

### AC3 新密碼不符規則被拒絕
- Given 使用者已登入
- When 新密碼少於 8 字元、超過 128 字元、屬常見密碼清單、與帳號相同，或兩次輸入不一致
- Then 系統拒絕並說明原因，密碼不變

### AC4 首次登入強制變更
- Given 帳號標記為「首次登入須變更密碼」（US-014）
- When 使用者登入成功後嘗試存取任何其他需登入的頁面
- Then 一律導向變更密碼頁，完成變更前無法申請、審核或取消

### AC5 CSRF 與登入
- Given 請求缺少 CSRF Token，或使用者未登入
- When 送出變更密碼
- Then 分別回應 403／導向登入頁，密碼不變

## 商業規則與限制
- AGENTS.md 2.3：密碼至少 8 字元並檢查常見密碼。

## 假設
- 第一版不提供「忘記密碼」自助重設（需 Email 流程），由承辦人重設（US-014 AC6）。

## 相依項目
- US-013、US-014。

## 資安考量
- 權限：只能變更自己的密碼，不接受 `user_id` 參數。
- 日誌不記錄任何密碼內容。
- 常見密碼清單以檔案形式隨程式提供，讀取時指定 `encoding='utf-8'`。
