# US-006 承辦人審核借用申請（核准／駁回）

## User Story(使用者故事)
身為課外組承辦人，我想要在系統中查看待審核的場地借用申請並核准或駁回，以便依規定把關活動，讓社團及時知道結果。

## 驗收條件（Acceptance Criteria）
### AC1 查看待審清單
- Given 承辦人已登入，系統有 5 筆「審核中」申請
- When 開啟「待審核申請」頁
- Then 依活動日期由近到遠列出 5 筆申請：申請編號、社團、申請人、場地、日期、時段、活動名稱、送出時間；可依場地與日期區間篩選

### AC2 核准申請（R-12、R-16）
- Given 申請 10 狀態為「審核中」，活動日期在未來，且該日期不在不開放日期內
- When 承辦人在明細頁按「核准」（可選填備註）
- Then 申請狀態變為「已核准」，記錄審核人與時間，狀態歷程新增一筆；借用狀況頁（US-002）顯示為已核准；寫入安全日誌

### AC3 駁回申請須填原因
- Given 申請 11 狀態為「審核中」
- When 承辦人按「駁回」且填寫原因（1～500 字）
- Then 申請狀態變為「已駁回」，時段立即釋放，學生可在 US-005 看到原因

### AC4 駁回未填原因被拒絕
- Given 申請 11 狀態為「審核中」
- When 承辦人按「駁回」但原因為空白
- Then 系統拒絕操作並提示「請填寫駁回原因」，狀態不變

### AC5 只能審核「審核中」的申請
- Given 申請狀態為已核准、已駁回或已取消
- When 承辦人（或竄改請求）對其送出核准／駁回
- Then 系統拒絕（409），顯示「此申請目前狀態無法審核」，狀態不變

### AC6 不開放日期或已過期的申請不能核准
- Given 申請送出後，承辦人才把該日期設為不開放（例如臨時的大型考試，R-05），或活動日期已過
- When 承辦人按「核准」
- Then 系統拒絕核准並提示原因（建議改為駁回或由 US-012 取消），狀態不變

### AC7 學生不能審核
- Given 使用者角色為學生
- When 開啟待審頁或對審核端點送出 POST
- Then 系統回應 403，並記錄權限拒絕的安全日誌

### AC8 未登入不能審核
- Given 訪客未登入
- When 對審核端點送出請求
- Then 導向登入頁或回應 401，狀態不變

### AC9 CSRF 防護
- Given 承辦人已登入
- When 核准／駁回請求缺少或帶錯誤的 CSRF Token
- Then 系統回應 403，狀態不變

### AC10 併發審核
- Given 兩位承辦人同時對同一筆審核中的申請，一位核准、一位駁回
- When 兩個請求併發處理
- Then 只有先完成的操作生效，另一位收到「此申請目前狀態無法審核」（狀態轉換需在 transaction 中以目前狀態為條件更新）

## 商業規則與限制
- R-12：固定與臨時借用都須經課外組承辦人審核。
- R-16：活動未經核准前不得舉辦。
- 狀態轉換：審核中 → 已核准／已駁回。不提供退回補件；資料不完整一律駁回並填寫原因，由社團重新申請（使用者決定，2026-11-06）。
- 固定保留時段（US-009）的每次使用申請，與臨時借用申請以相同流程審核。

## 假設
- 採 README 第 4 節建議：**不納入會簽單位**，由課外組承辦人單一關卡審核。
- 所有承辦人都可審核所有場地的申請（第一版不依場地分派承辦人）。
- 審核結果以系統內狀態與原因通知，不寄 Email。

## 資安考量
- 權限：僅 `staff` 角色可審核，service 層檢查，預設拒絕。
- 輸入驗證：原因 1～500 字，申請 id 為正整數，動作為列舉白名單（approve / reject）。
- 日誌：記錄審核事件（申請 id、審核人 id、結果），不記錄個資。
- CSRF Token 必驗。
