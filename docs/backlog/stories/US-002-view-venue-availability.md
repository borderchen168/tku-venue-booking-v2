# US-002 公開查看場地借用狀況

## User Story(使用者故事)
身為任何訪客（不需登入），我想要依場地與日期查看哪些時段已被借用、哪些日期不開放，以便在申請前找到可用的空檔。

## 驗收條件（Acceptance Criteria）
### AC1 未登入查看單一場地的週借用狀況
- Given 場地「驚聲廣場」在 2026-11-16（一）有一筆已核准借用 10:00–12:00、一筆審核中借用 14:00–16:00；今天 ≤ 2026-11-16 的 R-13 最晚申請日
- When 未登入訪客開啟該場地的借用狀況頁並選擇包含 2026-11-16 的那一週
- Then 以週檢視列出 08:00–22:00（R-01）的時段，10:00–12:00 標示「已核准」、14:00–16:00 標示「審核中」，其餘空閒時段標示「可申請」；時間以 Asia/Taipei 顯示
- 且 空閒時段的標示依日期而定，規則見 AC8（「可申請」只出現在可申請日期）

### AC2 公開資訊僅限必要欄位
- Given 上述借用存在
- When 訪客查看借用狀況
- Then 每筆借用只顯示：場地、日期、起訖時間、活動名稱、主辦社團、狀態；**不顯示**申請人姓名、學號、帳號、聯絡方式、活動說明與附件

### AC3 已取消、已駁回的申請不佔用時段
- Given 某時段的申請狀態為「已取消」或「已駁回」
- When 訪客查看借用狀況
- Then 該申請不顯示，該時段視為空閒，依 AC8 標示（例如可申請日期標示「可申請」）

### AC4 不開放日期標示
- Given 承辦人設定 2026-11-23 至 2026-11-29 為「期中考週」不開放（R-04），且 2026-12-25 為國定假日（R-03）
- When 訪客查看包含上述日期的週
- Then 這些日期整天標示「不開放」並顯示原因類型（例如「考試週」、「國定假日」），不顯示為可申請

### AC5 日期參數驗證
- Given 訪客以網址帶入不合法的日期（例如 `2026-13-45`）或超出可查詢範圍（今天前後各 1 年以外）
- When 送出請求
- Then 系統回應 422 或導回本週，並顯示易懂的錯誤訊息，不顯示 stack trace

### AC6 學期區間以外的日期標示為不開放（R-02）
- Given 學期區間為 9/1～12/31、3/1～6/30（使用者決定），Sprint 1 尚未提供寒暑假開放時段設定（US-018）
- When 訪客查看包含 2026-12-28（一）～2027-01-03（日）的那一週
- Then 2026-12-28～2026-12-31 依一般規則顯示（空閒時段依 AC8 標示）；2027-01-01～2027-01-03 整天標示「不開放（非學期期間）」，不顯示為可申請；若該日同時是承辦人設定的不開放日期（AC4），以不開放日期的原因類型為準（與 US-004 不開放優先的檢查順序一致）

### AC7 「申請此場地」連結只出現在可申請的日期
- Given 學生已登入，今天是 2026-11-16（一）；查看的週內同時有：學期內一般日期、不開放日期（AC4）、學期區間以外的日期（AC6）、已超過 R-13 最晚申請日的日期（例如 2026-11-20（五），最晚申請日為 2026-11-13）
- When 學生開啟該場地的週檢視
- Then 「申請此場地」連結（導向申請頁並預填場地與日期）**只**出現在可申請日期（定義見 AC8：在學期區間內、非不開放日、今天 ≤ R-13 最晚申請日）；其他日期不顯示該連結
- 且 未登入訪客與承辦人帳號一律不顯示「申請此場地」連結
- 且 本條只影響畫面上的連結；即使使用者自行組出申請網址，送出時仍由 US-004 的規則（AC10、AC11、AC17）在伺服器端拒絕

### AC8 空閒時段依日期標示「可申請」或「已過申請期限」
- Given 今天是 2026-11-16（一）；查看的週內同時有：可申請日期（在學期區間內、非不開放日、今天 ≤ R-13 最晚申請日）、已超過 R-13 最晚申請日的學期內非不開放日（例如 2026-11-20（五），最晚申請日為 2026-11-13）、今天以前的過去日期、不開放日期（AC4）、學期區間以外的日期（AC6）
- When 任何人（含未登入訪客、學生、承辦人）開啟該場地的週檢視
- Then 可申請日期的空閒時段標示「可申請」
- 且 在學期區間內、非不開放日、但今天已超過 R-13 最晚申請日的日期（**含過去日期**），空閒時段標示「已過申請期限」，不標示「可申請」
- 且 不開放日期依 AC4 整天標示「不開放」與原因類型；學期區間以外的日期依 AC6 整天標示「不開放（非學期期間）」；兩者都不標示「可申請」或「已過申請期限」
- 且 已核准、審核中的佔用時段在任何日期都依 AC1 標示「已核准」「審核中」，不受本條影響
- 且 本條的「可申請日期」與 AC7 顯示「申請此場地」連結的日期判斷完全相同（設計上同為 `bookable`）

## 商業規則與限制
- R-01：顯示 08:00–22:00。
- R-02～R-05：不開放日期／期間由 US-017、US-018 維護的資料決定；Sprint 1 學期區間外日期一律標示不開放（AC6）。
- R-13：最晚申請日計算與 US-004 相同（工作天＝週一～週五），用於 AC7 的連結顯示與 AC8 的「可申請／已過申請期限」標示。
- 申請狀態只有：審核中（pending）、已核准（approved）、已駁回（rejected）、已取消（cancelled）；佔用時段的狀態：審核中、已核准。不提供退回補件。
- 未來擴充（不屬於本 Story 的 Sprint 1 驗收）：
  - 固定保留時段（US-009）以「固定保留（社團名稱）」標示為佔用，驗收條件見 US-009 AC5。
  - 寒暑假日期（學期區間 9/1～12/31、3/1～6/30 以外）依 US-018 的開放時段顯示，未設定開放時段的寒暑假日期整天標示「不開放（寒暑假）」，驗收條件見 US-018。

## 假設
- 採 README 第 4 節建議：公開資訊只顯示場地、時段、活動名稱與主辦社團，不顯示申請人個資。
- 「審核中」的申請也佔用時段（先申請先佔），避免多個社團同時申請同一時段後再由承辦人取捨。
- 第一版提供「單一場地 × 週檢視」；不提供全部場地的總覽矩陣（可列為後續改善）。
- Sprint 1 週檢視把學期區間（9/1～12/31、3/1～6/30）以外的日期標示為「不開放（非學期期間）」，避免頁面顯示可申請但送出必被拒；理由是使用者已決定學期外日期一律拒絕申請（US-004 AC17）。US-018 完成後，寒暑假改依開放時段設定顯示（見上方「未來擴充」）（主對話同意 SA 暫定做法，2026-11-06，見 ADR-006、overview.md 第 11 節 #4）。
- 「申請此場地」連結只是操作便利，不是授權或規則檢查的依據；規則以 US-004 伺服器端檢查為準。
- 空閒時段只在可申請日期標「可申請」，已過 R-13 最晚申請日（含過去日期）的學期內非不開放日標「已過申請期限」（主對話決定，2026-11-06，修正 AC1 與 AC7 的不一致，新增 AC8）。

## 資安考量
- 權限：公開唯讀，不需登入；查詢層只選取公開欄位，避免個資外洩（ASVS V8 資料保護）。
- 輸入驗證：`venue_id` 為正整數、`week_start` 為合法 ISO 日期且在允許範圍內。
- 輸出：活動名稱、社團名稱由使用者輸入，必須經 autoescape 輸出（CWE-79）。
