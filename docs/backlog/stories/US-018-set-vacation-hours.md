# US-018 承辦人設定寒暑假開放時段

## User Story(使用者故事)
身為課外組承辦人，我想要設定寒暑假中哪些日期開放以及每日開放時段，以便系統依課外組公告的寒暑假開放時間（R-02）檢查申請，未公告開放的寒暑假日期則自動不開放。

## 驗收條件（Acceptance Criteria）
### AC1 設定寒暑假開放規則
- Given 承辦人已登入
- When 設定期間 2027-01-18～2027-02-21、每日開放時段 09:00–17:00、名稱「115 學年度寒假」後送出
- Then 建立規則；該期間借用狀況頁（US-002）只顯示 09:00–17:00 可申請

### AC2 依寒暑假時段檢查申請（R-02）
- Given 上述寒假規則存在
- When 學生申請 2027-02-01 16:00–18:00
- Then 系統拒絕，提示「該日開放時段為 09:00–17:00」

### AC3 未設定開放時段的寒暑假日期不開放
- Given 2027-01-05 不在學期區間內（屬寒假），且沒有任何寒暑假開放規則涵蓋該日
- When 學生申請 2027-01-05 的任何時段，或訪客查看該日借用狀況
- Then 申請被拒絕，顯示「寒暑假期間未開放借用」；借用狀況頁該日整天標示「不開放（寒暑假）」

### AC4 寒暑假期間不開放日期仍優先
- Given 寒假規則期間內某日同時被設為不開放（US-017）
- When 學生申請該日
- Then 以不開放為準，申請被拒絕

### AC5 學期區間內不受寒暑假規則影響
- Given 學期區間（9/1～12/31、3/1～6/30）內的日期
- When 學生申請
- Then 一律以 R-01 08:00–22:00 檢查

### AC6 時段與期間驗證
- Given 承辦人輸入開始時間不早於結束時間、時段超出 08:00–22:00、非 30 分鐘倍數、起日晚於迄日、期間含學期區間內的日期（例如 2027-02-20～2027-03-05），或與既有寒暑假規則期間重疊
- When 送出
- Then 系統拒絕並說明原因

### AC7 學生不能設定
- Given 使用者角色為學生或未登入
- When 存取設定頁或端點
- Then 分別回應 403（記錄權限拒絕日誌）或導向登入頁

### AC8 CSRF 防護
- Given 請求缺少 CSRF Token
- When 新增、編輯或刪除規則
- Then 系統回應 403，資料不變

## 商業規則與限制
- 學期區間（使用者決定，暫定）：每年 9/1～12/31（上學期）、3/1～6/30（下學期）；其餘日期（1/1～2 月底、7/1～8/31）視為寒暑假。
- R-01：學期區間內 08:00–22:00。
- R-02：寒暑假開放時間由課外組另行公告，以本 Story 的規則設定。

## 假設
- 寒暑假日期若沒有任何開放規則涵蓋，**視為不開放**（使用者決定，2026-11-06）。
- 寒暑假規則適用全部場地，每日相同時段；寒暑假時段不超出 08:00–22:00。
- 學期區間以月日固定判斷，不需承辦人每年設定（設定方式依 T-001 架構設計）。
