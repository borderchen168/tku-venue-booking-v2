# EP-004 帳號、角色與社團

## 目標
支撐性 Epic。使用案例 2、3 都需要辨識「誰」在操作：學生只能以自己負責的社團申請、只能取消自己的申請；
承辦人才能審核與取消他人借用。實務上申請單位是**社團**（README 第 4 節），因此需要帳號、角色與社團的基本資料，
作為存取控制（OWASP A01）與 IDOR 防護的基礎。

## 範圍
- 包含：
  - 本機帳號登入、登出（argon2 雜湊、Rate Limit、Session 安全設定）。
  - 兩種角色：`student`（學生／社團負責人）、`staff`（課外組承辦人）。
  - 承辦人維護社團與學生帳號（建立、停用、指定社團負責人）。
  - 使用者變更密碼，首次登入強制變更初始密碼。
  - 第一個承辦人帳號以管理指令（CLI）建立。
  - 登入濫用防護的補強：應用程式層 IP 頻率限制（US-021）、承辦人 Web 解除帳號鎖定（US-022）。
- 不包含：
  - 學生自行註冊（第一版不開放，帳號由承辦人建立）。
  - 學校 SSO(單一登入)（AGENTS.md 第 5 節列為後續階段）。
  - 忘記密碼自助重設（第一版由承辦人重設）。
  - 社團成員名冊、社團評鑑等社團管理功能。
